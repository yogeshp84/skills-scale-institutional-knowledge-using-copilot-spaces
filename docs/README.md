# OctoAcme Project Management Docs

This README provides a brief summary of OctoAcme's project management processes and direct links to each process document in the docs/ folder.

## Quick Overview
OctoAcme follows a lightweight, stage-based approach focused on delivering customer value iteratively while keeping communication and risk management explicit.

Key stages:
- Initiation: capture the problem, stakeholders, and measurable success criteria (one-pager).
- Planning: convert approved initiatives into prioritized, estimated backlog items and a release plan.
- Execution & Tracking: run timeboxed work (sprints/iterations), track progress on a project board, and use CI/PR workflows for quality.
- Risks & Communication: maintain a risk register, escalate blockers through defined paths, and keep stakeholders informed.
- Release & Deployment: follow pre-release checks, run smoke tests, and document rollback plans.
- Retrospective & Continuous Improvement: capture learnings, create action items, and measure improvement.

## How we run work (short)
- Small, testable increments with clear acceptance criteria and Definition of Done.
- Use project boards to track Backlog -> Ready -> In Progress -> In Review -> QA -> Done.
- Pull Requests should include issue links, acceptance criteria, and pass CI/linting before review.
- Require at least one approval before merging and keep PRs small when possible.
